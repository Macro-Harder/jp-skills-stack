# Team Staffing

## What it is
This skill gives the team sizes and staffing rules to use whenever a team is seated for any stage of a build. Sizes are set by tier, in the order Low, Medium, High, Extra High, and Plaid. The sizes are minimums, never ceilings, and never reduced. A size change governs every stage not yet closed, while stages already closed keep the staffing they closed with.

The ladder in that tier order is as follows. Note taking: 4, 4, 6, 8, 10. Pre plan research: 5, 9, 15, 25, 35. Research: 3, 6, 12, 24, 48. Imagination: 2, 4, 6, 8, 10. Design: 2, 3, 4, 8, 12. Build: 3, 5, 7, 11, 15. Audit, per audit: 3, 9, 21, 35, 35. Logic audit, per loop: 5, 15, 25, 35, 35. Review board: at least 3 at every tier, sitting at every step.

A member is a distinct agent. One agent never wears several hats or covers two seats, with the single exception of the small tier audit team of at least 3 wearing several colour lenses. Agents are a fluid pool of unique roles divided by family, so builders are seated only from the builder pool, auditors only from the auditor pool, and so on. Fluidity runs inside a family and across steps and rounds, never across families. The Manager picks the members a plan calls for, best fitted to the work.

Carried seats sit on top of the base numbers. Every design and build team carries a fold in tracer and a principles agent as distinct seats. Every design team carries a contrarian. Every build carries a live proof owner from mid build on. Parallel research carries a clerk keeping the shared evidence register. Any agent directly modifying code sits in a build team, never solo, and each build team member builds from a different perspective. A stage that ran short on distinct agents does not count as staffed. It is restaffed for any work not yet closed, and the roster is stated stage by stage in the report.

Five warnings each stop the step: a standing role has nobody in it, the danger list is out of date, a record list was never converted into the system, a role is filled but the person only watches and does no work, and the practice drill for attacking the gates was missed.

## Example
A build moves to its design stage at the High tier. The base design size from the ladder is 4. On top of that, the team carries a fold in tracer, a principles agent, and a contrarian as distinct seats, each held by a different agent, with a review board of at least 3 sitting at the step. If only 3 distinct agents were seated for the base team, the stage does not count as staffed and is restaffed for work not yet closed, with the roster stated in the report.

## How to use it
Place the folder in an agent skills library. The agent loads the skill whenever a team is seated for any stage of a build. A person can also ask directly in plain words, for example by asking how large a team should be for a stage at a given tier, or by asking for a roster to be checked against the ladder. The person supplies the stage and the tier so the correct row and column can be read.

## For agents
Agent use is the same as the use already described, with the added duties that the agent seats members only from the correct family pool, adds the carried seats on top of the base numbers as distinct agents, and treats any of the five warnings as a stop for the step.
