# Red Flag Check

## What it is
This skill runs one checklist pass over a step's handovers, records, and reports against the eleven annex red flags of R-248, and names every flag present or absent inside the step ruling or the gate record being written. It loads at one moment only: an approval gate where the Auditor is writing a step ruling, or the release gate where the Release-gate Keeper is writing a gate record, and the eleven flags are not yet named in that writing. The moment is recognised by what is being written, not by the document's title. It never runs for an audit round as such, for the repo tree checks at the release gate, or for a gate verdict or outcome.

The check runs in two halves in a fixed order. The first half builds the evidence set from the step's handovers, records, and reports, at the release gate from those of every step in the build, and lists that set in the ruling before any judging. The second half judges each flag against the listed set only, in annex order, with no sampling, and writes the naming block into the ruling itself. Each flag line takes a recorded form: present; absent, with the search scope stated beside it; or not named for want of evidence, which states that the check is not completed for that flag and the gate has not run in full. Flag 11, the flag for protocol fields invented rather than read from the spec version in use, has a split form for the case where part of the records names a spec version and part does not.

For each flag named present, the block carries a finding line with the severity judged under the severity rules in force, a touch line naming which of closure, staffing integrity, verification, or secrets the flag touches, a disposition line, and, where one of those four subjects is touched, a closure block line stating that the step does not close over the flag until it is remedied and the remedy recorded, or the closure carries it under the findings and qualifications rules. Missing inputs fall in three classes, each with stated handling: a missing evidence item is recorded as a gap beside each affected naming; a missing spec version limits flag 11 to the parts of the records that name one; and missing severity rules pause the finding lines only, while the flags are still named. Where a naming rests on a construction of the skill itself, such as the class 2 handling for flag 11, a construction citation line stands beside it citing the skill red-flag-check at the point of use; a statement elsewhere that the skill is loaded is not the citation. The skill also covers the later work in a ruling already written: remedy rechecks, dispute rechecks, and the completion of a partial check. The flag list is carried in full in the skill's Reference section, quoted from its source in the build flow standing document, and the severity rules are pointed to at their source and not carried.

## Example
A step finishes and the Auditor writes its ruling. The ruling records the audit findings with severities, but it names none of the eleven flags, so the skill is due and loads. The evidence set is built from the step's handover, the coordinator completion reports, the step records, and the roster, and listed in the ruling. Judging against that set, the records show a coordinator tour that ended with no successor seated and no checkpoint packet at the head of the handover. The flag for that pattern is named present, with a finding line at the judged severity, a touch line naming closure and staffing integrity, and the closure block line after it. The remaining flags are named absent, each with the scope that was searched, except one whose only evidence record is missing, which is named not named for want of evidence with a gap note beside it. The block closes with the cross reference line, which states that the verdict and the outcome for the gate are recorded in their own parts of the ruling and that the block supplies findings to the ruling and nothing more. A notice listing the present flag is sent to the step owner the same day.

## How to use it
Place the folder in an agent skills library. The agent loads the skill when a step ruling is being written at an approval gate, when a gate record is being written at the release gate, when a second checker named in a ruling is writing the flag naming for the part of the records the first checker authored, and for the recheck and completion work in a ruling already written, in each case where the flags in scope are not yet named in that writing. A person can also ask directly in plain words, for example by asking for the red flag check to be run over a named step's records for its ruling.

The inputs are the records of the step: its handovers and completion reports, its records and reports as a whole set, its roster and spawn records, its delegation briefs, and the ruling or gate record draft the naming block will sit in. At the release gate the inputs are those records for every step in the build, together with the earlier steps' naming blocks. The annex flag list is carried by the skill itself. The severity rules are read at their source in the build flow documents; the skill points to them and carries none of their text. Where an input is missing, the run proceeds under the missing input class that covers it and records the gap, the limit, or the pause in the ruling, rather than stopping or guessing.

## For agents
When the skill loads, follow its six steps in order: name the gate, the scope, and the checker; build the evidence set and list it before judging; judge each flag in annex order against that set only; write the naming block inside the ruling in the recorded forms and the assembly order the skill states; give the notice and record any disputes; and run the recheck, completion, and close work as the ruling needs it. Cite every construction you rely on to the skill red-flag-check at its point of use, in the forms the skill states. Never produce a preparatory or dry run flag pass as this skill's run, never name a flag absent on a search of less than the whole of its evidence row, and never use the skill for an audit round, a repo tree check, a skip decision, a principles check, a fold trace, or a verdict or outcome question. Where the Auditor approval gate skill is running the gate, this skill runs inside it as the required companion and owns the check, its flag list, its evidence set, its judging, and its naming block.
