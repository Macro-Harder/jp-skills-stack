# Release Gate

## What it is
This skill is the checklist for the release gate stage of a build, and for any repo about to be called shipped. A single release gate keeper owns the checklist end to end and alone passes or fails it. Every item is checked on evidence, not on the build's own say so.

The gate checks eight things. It clones the public repo fresh and sweeps the whole tree, file contents as well as file names, for design material, audit papers, registers, and anything that is not the system, its tests, its README, and its license. It checks that the public repo carries Apache 2.0 and that the copyright holder line reads exactly "J.P. Picard aka Macro-Harder", with third party work keeping its own license and credit untouched. It checks that no briefs, plans, audit docs, or build flow working papers are in the public repo, while benchmarks and eval harnesses are allowed to ship. It checks that the repo never names an AI or agent as the thing that built it, with no generated by lines, provenance stamps, or origin story paragraphs, while agents named as the system users stay as product content. It checks that no text reads as obviously AI written, with no em dashes and no heavy dash use. It checks that the README contains end user content only, covering what the product is, what it does, and how to install and use it, with no build process, registers, step talk, or status narration. It checks install verification by installing from the clean clone using the README steps and running the product. It checks that the full test suite passes in the fresh clone, not only in the working tree.

The verdict is pass, or fail with the failing items named. A failed gate sends the build back into its fix loops, and the gate is re run whole, not only on the fixed items. The gate result and its evidence go in the project private design repo.

## Example
A build is ready to ship and its public repo is submitted for the gate. The keeper clones the repo fresh, sweeps the contents, checks the license and holder line, reads the README, installs the product from the clone following the README steps, and runs the full test suite in that clone. If the sweep finds a design plan in the tree or the install steps do not work from the clone, the gate fails, those items are named, and the build returns to its fix loops. The gate is then run again in full.

## How to use it
Place the folder in an agent skills library. The agent loads the skill at the release gate stage of a build, or when a repo is about to be called shipped. A person can also ask directly in plain words, for example by asking for the release gate to be run on a repo before it is called shipped. The skill itself does not list extra inputs the person must supply beyond identifying the build or repo to be gated.

## For agents
Agent use is the same as the use already described, with the added point that the agent acting as release gate keeper applies the eight checks on evidence, names any failing items, and records the result and evidence in the project private design repo.
