# Ruling Walkthrough Pacing

## Set the format before the first item

- Confirm the channel before starting, because voice and text use different formats in this method.

- State the format you will follow in one short line and then start, without adding background or filler.

- Treat any pacing rule the user gives during the walkthrough as binding for every later item, not only for the item being discussed.

- Keep a running record of each ruling as it is made, and record nothing for an item the user has paused or left unfinished.

## Walk one item in voice

- Open each question by stating how many parts it has, and how many sections it has when sections exist.

- Read the problem for one part only, then stop and wait.

- Do not read the next part until the user tells you to move on.

- Do not move to part two of a question until part one has a solution the user accepts.

- Present one option at a time within a part, then leave the user room to think before offering the next.

- Never re-read a question, a part or an option unless the user specifically asks you to re-read it.

- Keep each spoken turn brief and free of filler, so the user hears the problem and the count and nothing extra.

- Stay on the current question, and never fold parts of an earlier or later question into the one being ruled on.

## Walk one item in text

- Present the whole question at once in text, including all of its parts, when the user is working in text rather than on a voice call.

- Keep the text presentation to the problem and its options, without a preamble about the list as a whole.

- Wait for the ruling before presenting the next question.

- Apply the same no re-reading rule in text, and resend a question only when the user asks for it again.

## Close each ruling cleanly

- Restate the ruling the user made in their own terms, in one or two short lines.

- Write the ruling to the record the walkthrough is using before moving on, when a record file or log has been named for it.

- Name the next question by number only when the user signals they are ready for it.

- When the user pauses an item, mark it paused and unfinished, and do not submit, file or summarise a ruling for it.

## Alternatives for better results

- Offer to switch formats when the channel changes mid walkthrough, applying the voice format on calls and the whole question format in text.

- Offer a written list of the remaining question numbers only, without their content, when the user wants to see progress without breaking the pace.
