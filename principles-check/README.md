# Principles Check

## What it is
This skill is the loadable procedure for checking work against an adopted set of build principles. It is used by the principles agent on a design or build team, and whenever a decision needs checking against the set. The checklist itself is the adopted set kept at the path named in the skill, in Simple form, Advanced form with source question numbers, and Agentic form with rules P-01 to P-31. Where this skill and the set disagree, the set wins.

Every design team and every build team carries a principles agent as a distinct seat. Its only job is checking the team work against the adopted set and flagging any breach. One agent never serves as the principles agent for two teams at once.

To check, the agent reads the piece of work being checked, walks the Agentic form of the set plus any Simple form principle the work touches, and tests the work against each principle it engages. For each breach found, it records the principle number, what the work does, and what the principle requires. Breaches are reported to the team before the stage closes. A flagged breach is either fixed or carried up as a design question. It is never silently waived by the team.

Headline principles that come up most often include quality over speed, security first and then structural strength with usefulness to a real user as the main judge, a structural weakness meaning not done even if the thing works, never reducing intelligence use or team sizes set for the work, and simpler beating clever under the future problems test.

## Example
A design team is about to close a stage on a plan that cuts its review team size to save time. The principles agent walks the set against the plan, records the breach with the principle number, what the plan does, and what the principle requires, and reports it before the stage closes. The stage does not close over the unflagged breach, and the flagged item is either fixed or carried up as a design question.

## How to use it
Place the folder in an agent skills library. The agent loads the skill when it sits as the principles agent on a design or build team, or when a decision needs checking against the set. A person can also ask for the work directly in plain words, for example by asking for a brief, a plan, a code change, or a decision to be checked against the principles.

The piece of work to be checked is the input: a brief section, a plan, a code change, or a decision.

## For agents
Agent use is the same check described above, performed as a distinct seat on one team at a time, with each breach recorded and reported before the stage closes.
