# Principles Check

Quick version, written 2026-11-14 outside the build flow. The checklist itself is Captain JP's adopted build principles set, kept at ~/workspace/goals/personal-principles-setup/files/BUILD-PRINCIPLES-SET-DRAFT.md (the Adopted Set: Simple form, Advanced form with source question numbers, and the Agentic form, rules P-01 to P-31). This skill is the loadable procedure for applying it. Where this skill and the set disagree, the set wins.

Use this skill as the principles agent on a design or build team, and whenever a decision needs checking against the set.

## The seat

Every design team and every build team carries a principles agent as a distinct seat. Its only job is checking the team's work against the adopted set and flagging any breach. One agent never serves as the principles agent for two teams at once.

## How to check

1. Read the piece of work being checked: the brief section, the plan, the code change, the decision.
2. Walk the Agentic form of the set, P-01 to P-31, plus any Simple-form principle the work touches, and test the work against each one it engages.
3. For each breach found, record: the principle number, what the work does, and what the principle requires.
4. Report breaches to the team before the stage closes. A stage does not close over an unflagged breach, and a flagged breach is either fixed or carried up as a design question; it is never silently waived by the team.

## The headline principles

These come up most often; the full set still governs.

- Quality beats speed. Thorough and precise work over quick work, always.
- Security first, then structural strength, then usefulness to a real user as the main judge.
- A structural weakness means not done, even if the thing works.
- Never reduce intelligence use: no settlement may shrink a team or cut the intelligence applied to the work, and team sizes Captain JP set are never reduced.
- Simpler beats clever, judged by the future-problems test.
- Unasked improvements are allowed, decided by Muse, or the idea goes into the next version's brief.
