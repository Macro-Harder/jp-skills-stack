# Requirement Grammar

## What it is
This skill has one job: writing requirement statements in a defined grammar, or running presence checks over the forms that the source states on supplied statements, and flagging every gap the run raises under its stated checks. It applies only to briefs, plans, and new rules. It is never for general writing help, document verification, or gate rulings, and it issues no conformance verdict and no completeness ruling on a document.

For drafting, it writes requirement statements in the grammar in the patterns the caller names, and gives each new statement its failure case. For checking, it runs presence checks over the stated forms on supplied statements, before or after drafting. The five patterns named in the source are ubiquitous, event driven with When for the trigger, state driven with While for the precondition, optional feature, and unwanted behaviour. The skill constructs no form for the ubiquitous and optional feature patterns, and returns drafting material aimed at those patterns as supplied, marked as returned material. A failure case is written in the quoted form: "If an undesired situation occurs, then the stated response follows." A missing failure case on a new rule is reported as incomplete, while at statement level in a brief or plan it is a flag only.

A run starts with triage. Caller identified statements in a claimed artefact are bound and are worked. Material the source places outside the grammar force is not bound and is returned untouched. Everything unclear, and statements in artefacts the grammar does not claim, are undecided and are parked, never worked. The skill applies no test of its own for what a requirement statement is, and claims inside the material itself do not count as caller identification. Where a response is stated, the response clause stands last. Where no response is stated, no response is invented. A vocabulary second pass checks the closed keyword set MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY, flags words outside the set used as obligation words, flags a MUST with no visible rationing ground, and never rewrites or arbitrates. Contested force is flagged and routed to the Auditor.

One run produces one output: a statements block headed by a triage record, a flags block with one entry per gap per run, and a closing gap index strip listing the gap numbers. Gapped statements are completed only as far as the source supports, with the gap marked, and no subject, response, or separation is invented.

## Example
A caller supplies drafting material for a plan, identifies which sentences are requirement statements, names one as event driven, and asks for statements in the grammar. The run triages the material, works the bound statement so it shows When for its trigger with the response clause last, adds its failure case in the stated form, runs the vocabulary pass, and returns the statements block, the flags block for any gaps raised, and the gap index strip. Material the caller did not identify is parked as undecided and listed in the triage record, not worked.

## How to use it
Place the folder in an agent skills library. The agent loads the skill when the task is drafting statements that must follow the requirement grammar, or checking supplied statements for the presence of the stated forms, and when the caller can identify the statements and the artefact they belong to. A person can also ask directly in plain words, for example by asking for requirement statements for a brief to be drafted in the grammar, or for supplied statements to be checked.

The caller must supply the inputs the skill states: the material, either statements to check or drafting material to write from; caller identification of which sentences are requirement statements, their pattern names where named, response clause marks where marked, and revision marks where the material is pre existing; the artefact, which must be a brief, a plan, or a new rule; and revision status for pre existing material, per statement. Where part of the input is missing, the run proceeds on the supplied and identified parts only and parks the rest as undecided with flags.

## For agents
When the skill loads, the agent follows its procedure in order: triage, write or check each bound statement under its caller named pattern, add failure cases, run presence checks on a checking run, run the vocabulary second pass, and assemble the output in the stated form. The agent never names a pattern on its own authority, never moves a caller supplied failure case on a checking run, and never issues a gate ruling. Gate rulings, SHOULD deviation validation, and force arbitration stay with the Auditor. Where the scope of the work itself is undecided, the agent routes the caller to grill mode first.
